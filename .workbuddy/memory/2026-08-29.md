### 重读发现的代码问题（未在 AGENTS.md 记录，待确认是否修）
1. **写信未校验每日上限**：`send` 分支只校验 content 非空，`max_daily_letters` 仅在 `list` 接口计算 remainingToday 返回，后端不拦截超限发信。
2. **回信后未置未读**：`generate_reply` 成功后只设 status=REPLIED，未设 `unread=True` → `unread_count` 恒为 0，App 端无未读红点。
3. **`endpoint()` 缺默认值**：1.2.10 给 `is_letter_flow` 加了 `LISTENER.get("path_prefix", …)`，但 `endpoint()` 仍硬取 `LISTENER["path_prefix"]`，config 缺 listener 段时 request 会 KeyError。
4. **拦截不校验 host**：`is_letter_flow` 只看 path 前缀，`LOGIN_PATHS`（/signIn 等）也不看 host → 任何 host 的匹配请求都会被 mock，存在过度拦截。
5. **`start_proxy` 断网风险未修**：1.2.10 只修了 `toggle_proxy`（先启动再开代理），但 `start_proxy` 仍是先 `set_proxy(True)` 再 Popen，启动失败会指向死代理。
6. **GUI 无 fallback_provider 编辑项**：1.2.7 的 fallback_provider / providers.<name> 只能手工改 config.json。
7. `list` 接口 `PERSONA["max_daily_letters"]` 硬取，config 缺 persona 段会 KeyError（同问题 3 类）。

### 约定
- 改 addon 必须同步 4 处（gui/ + 便携版 + 源码 + release），改完用 md5 校验一致性。
- 手动启动 mitmdump 必须带 `--set confdir=<dir>/runtime/certs`，否则证书不符导致 TLS 握手全失败。
