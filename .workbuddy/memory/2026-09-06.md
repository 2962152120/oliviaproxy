## 通读源码（gui/olivia_letter_proxy.py 1082 行 + gui/olivia_gui.py 1110 行）

### 重要：两处硬取是「潜伏」不是「活跃」
config.json 顶层段为 openai/persona/listener/memory/reply/video/tts/dispatch，`listener` 有 `path_prefix`，`persona` 有 `max_daily_letters=3` → `endpoint()` 与 `list` 分支的 KeyError **当前不会触发**，只有用户删掉这两段才会炸。修复优先级因此低于此前判断。

### addon 确认的缺陷
1. `send` 不校验每日上限：`max_daily_letters` 只用于 `list` 算 `remainingToday`，后端不拦。
2. `generate_reply` 成功只设 `status=REPLIED`，**不设 `unread=True`** → `count_unread()` 恒 0，App 无未读红点（种子信 2001 是手写 `unread:True`）。
3. `send` 里 `remember("user", content)` 在 `Thread(...).start()` **之后**执行，靠 20s 延时侥幸躲过竞态；若 delay 调小会漏记忆。
4. 视频 fallback 链最坏耗时叠加：主 provider 跑满 600s 超时后才切 fallback，再跑 600s = 20 分钟。
5. `tts_minimax` 的 hex/base64 判别：base64 结果若偶数长且恰好全为 hex 字符会误判（概率极低）。
6. `ensure_video_server()` 失败时 `_video_server_ref` 为 None 可重试，但 `video_url_for()` 无条件返回 URL。
7. `stop_proxy` 无条件 `set_proxy(False)`；`restore_backup()` **不还原 ProxyOverride**（备份写进去了却没读出来）。
8. 拦截不校验 host：`LOGIN_PATHS` 与 `/toy/` 兜底 200 对任意 host 生效（为配合 PC 端补丁，属有意，但副作用面变大）。

### GUI 确认的缺陷
9. `_drain()` 第 1033 行 `self.root.after(0, self._log, text)` 无保护 —— 窗口销毁后后台线程回调会抛 `RuntimeError: main thread is not in main loop`。与 1.2.11 修过的 `_enable_proxy_when_ready` 是同一类问题，那次只补了一处。
10. `_poll_cert()` 每 8s 起一个 `certutil -user -store Root` 子进程，长期挂着有开销。
11. `_poll()` 每 2s → `refresh_status()` → `count_letters()` 读一次 letters.json（30 次/分钟）。
12. `cert_is_installed()` 只判 `"mitmproxy" in stdout`，可能误报。
13. GUI 仍无 `fallback_provider` 编辑框（1.2.7 起只能手改 config.json）。
14. `APP_VERSION` 仍显示 1.2.10，未体现 9/4 写信面板。
15. `save_config()` 整段覆盖 openai/persona，会丢 `top_p` 等 GUI 未暴露字段（`max_tokens` 已单独保留）。

### 结构要点（便于后续定位）
- addon 只挂 `request()` 一个钩子，无 `response()` → 未命中拦截的流量原样透传，设计正确。
- `json_response()` 无 `code` 键时自动包 `{"code":0,"message":"","data":...}`；GUI `_unwrap()` 依赖此约定取 `data`。
- 视频/TTS 均为「主→fallback」链 + `providers.<name>` 子块覆盖顶层配置，`_is_transient()` 判瞬时错误才回退。
- 视频回信落 `videos/<letter_id>.mp4`，由 8765 本地 HTTP 服务提供，`reply_type=3`(MIX_PLAY)。
- 写信面板直连 `http://127.0.0.1:8080`，绕开 App；轮询 detail 240s，`letterStatus==5` 判失败。
